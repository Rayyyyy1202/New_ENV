# 对标链接获取 · 两种方案对比

**用 RPA vs 不用 RPA,各自怎么解决同一个问题**

---

## 问题定义

根据装箱单清单,在 **亚马逊德国 amazon.de** 上按可自定义的要求,找到符合条件的对标商品链接并给出理由,人工审核后回写:

- **硬性要求**:原产地中国、排除注册品牌、材质匹配
- **条件门槛**:评论数(销量代理)、评分、相关性
- **择优目标**:最便宜,或最接近目标价

> 核心难点:亚马逊**没有**面向第三方的"任意竞品搜索"开放接口,且对自动抓取有**反爬**机制。链接要"真实、可核验、合规"。

无论哪种方案,**AI 判断层都一样**:电商语境翻译、语义向量匹配、多模态相关性评分、详情页材质/原产地抽取、品牌词研判 + EUIPO 商标核验、按要求筛选 + 择优、给出理由。**区别只在"取数管道"——靠 RPA 抓,还是靠 API/数据服务/半自动拿。**

---

## 方案 A:用 RPA(浏览器自动化实时抓亚马逊)

**实现路径**
工单 → AI 提取指令 + 解析装箱单 → AI 电商翻译 → 历史库语义检索 → **RPA 驱动真实浏览器**在 amazon.de 跑 5 种排序搜索、翻页抓候选、逐个打开详情页抓材质/原产地、谷歌反向图搜 → AI 多模态相关性 + 商标核验 → 按要求筛选 + 最便宜/目标价择优 → 回写并回群。

**技术栈**
Playwright / Selenium + 住宅代理池 + 验证码处理(打码平台 / AI)+ AI 视觉自愈选择器 + 任务队列 + 调度。

**优点**
- 拿到**真实、实时**的在售商品,含真实 `/dp/ASIN` 具体链接、实时价格与评论数
- 覆盖最全:任意品类、任意排序都能跑
- 数据最新,最适合报关估价与价格比对

**代价 / 风险**
- 反爬、验证码、IP 封禁 → 需住宅代理(按流量持续付费)
- 亚马逊改版需维护(即便 AI 视觉定位也要盯)
- 速度慢(每件数十秒)、基础设施重
- 合规灰区:可能触碰目标站 ToS,需控频与法务评估
- 上线周期长

---

## 方案 B:不用 RPA(API / 数据服务 + AI,或半自动)

不碰浏览器自动化,有三条子路径:

**B1 · 第三方电商数据 API**(Rainforest API / Oxylabs / Bright Data / Keepa 等)
本质是"别人替你抓",你调 API 直接拿结构化结果(标题、价格、评论、ASIN、图)。AI 仍做全部判断;商标用 **EUIPO TMview API**。

**B2 · 半自动 + AI(本演示形态)**
候选由人工搜索/粘贴或系统预置,AI 负责翻译、相关性、抽取、核验、择优、填表,人工只审核。

**B3 · 仅历史库语义匹配**
不上实时亚马逊,只在自建历史对标库里做语义检索,命中即复用。

**优点**
- **不碰反爬**:B1 把代理/验证码风险外包给数据商;B2/B3 根本不抓
- 上线快、维护轻、稳定(B1 有 SLA 保障)
- 合规更清晰(使用商用数据 API)
- B1 也能拿到真实 ASIN / 近实时价格

**代价 / 局限**
- B1 有 **API 调用费**(按条计费),字段/覆盖受数据商限制,且数据商本身也间接依赖抓取
- B2 需要人工提供候选,规模化差
- B3 覆盖不全(库里没有就没有)、非实时

---

## 维度对比

| 维度 | 方案 A · RPA | 方案 B · 不用 RPA |
|---|---|---|
| 实时数据 | ✅ 最实时 | B1 近实时 · B2/B3 较弱 |
| 真实具体 ASIN 链接 | ✅ | B1 ✅ · B2 看人工 · B3 历史 |
| 覆盖广度 | ✅ 任意品类/排序 | B1 较广(受数据商)· B3 仅历史 |
| 判断准确度(AI 层) | ✅ 强 | ✅ 强(完全一致) |
| 稳定性 | ⚠ 受反爬/改版影响 | ✅ 高(API SLA) |
| 维护成本 | 高(持续) | 低 |
| 反爬 / 验证码 | 自己扛 | B1 外包 · B2/B3 无 |
| 合规 | 灰区,需评估 | 较清晰(商用 API) |
| 上线速度 | 慢 | 快 |
| 成本结构 | 代理+基础设施+人力(固定+流量) | B1 按调用计费(变动)· B2 人力 |
| 规模化 | ✅(投入到位) | B1 ✅ · B2 ⚠ |

---

## 成本直觉

- **RPA(A)**:前期工程 + 长期代理/维护成本;适合**高频、大量、且必须拿最新真实 ASIN** 的场景。
- **数据 API(B1)**:零运维起步、按量付费;**中小量、要快上线**更划算;但量极大时单位成本可能反超自建 RPA。
- **半自动(B2)**:**最快落地、最稳**;适合 PoC、演示、低频业务。

---

## 总成本预估

> 粗估,仅供决策参考。基准假设:**月处理约 5,000 个商品对标**、按国内研发计;实际随业务量、服务商报价、合规要求浮动。

### 方案 A · RPA(自建实时抓)

| 项目 | 预估 |
|---|---|
| 一次性开发 | ¥15 万 – ¥30 万(约 2–4 人月) |
| 住宅代理(按流量) | ¥1,000 – ¥5,000 / 月 |
| 验证码 / 打码 | ¥300 – ¥1,000 / 月 |
| 服务器 / 调度 | ¥500 – ¥2,000 / 月 |
| LLM(翻译/相关性/抽取) | ¥500 – ¥2,000 / 月 |
| 反爬对抗 / 改版维护(人力) | ¥3,000 – ¥10,000 / 月 |
| **月度运营合计** | **约 ¥6,000 – ¥20,000 / 月** |
| 单件边际成本 | 约 ¥1 – ¥4 / 件 |
| **首年总成本(TCO)** | **约 ¥22 万 – ¥54 万** |

### 方案 B · 不用 RPA(B1 数据 API + AI)

| 项目 | 预估 |
|---|---|
| 一次性开发 | ¥6 万 – ¥15 万(约 1–2 人月) |
| 电商数据 API(按调用,随量线性) | ¥3,000 – ¥10,000 / 月 |
| LLM(翻译/相关性/抽取) | ¥500 – ¥2,000 / 月 |
| 服务器 | ¥300 – ¥1,000 / 月 |
| 轻量维护(人力) | ¥1,000 – ¥3,000 / 月 |
| **月度运营合计** | **约 ¥5,000 – ¥16,000 / 月** |
| 单件边际成本 | 约 ¥1 – ¥3 / 件 |
| **首年总成本(TCO)** | **约 ¥12 万 – ¥34 万** |

> 另:**方案 B2(半自动 + AI)** 一次性约 ¥3 万 – ¥8 万,月度主要是 LLM(¥几百 – ¥1,500)+ 人工提供候选的人力;最省、最快落地,适合先跑起来。
>
> **结论**:首年看,B1 比 A 省约 **¥10 万 – ¥20 万**且上线更快;当月处理量显著放大(如 5–10 万件/月)、或必须实时真实 ASIN 时,A 的单件成本优势才会体现,这时可转 A 或 A+B1 混合。

---

## 推荐:分阶段演进

1. **演示 / PoC** → 方案 B2(半自动 + AI,就是当前这套):零风险、最快让客户看到价值。
2. **正式上线 v1** → 方案 B1(第三方数据 API + AI):快、稳、合规清晰,能拿真实 ASIN,判断层不变。
3. **规模化 / 降本 / 要最全最新** → 引入方案 A(RPA),或 **A+B1 混合**(RPA 主抓、API 兜底)。
